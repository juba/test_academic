# Personal academic website template

The goal of this project is to provide a starting point for a personal website
which would allow a PhD student or a researcher to publish a presentation of
him/herself and his/her work.

The website generated by this template is visible here:

<https://lbbe.pages.in2p3.fr/poleinfo/academic_website/>

This project uses [Quarto](https://quarto.org) to create a static website from a
set of markdown files.

Quarto is a powerful publishing system which can be used for many different
tasks: literate programming, reproducible research, scientific paper writing,
document generation, etc. Here we will use it for its capability to generate a
static website.

To use this project you must know how to run terminal commands and edit text
files on your machine. This could be done via a tool like VSCode or Zed, but any
terminal and text editor is enough.

## Installation and usage

This project uses [pixi](https://pixi.prefix.dev/latest/) to make quarto
installation and management easier. The first step is to
[install pixi](https://pixi.prefix.dev/latest/installation/).

> [!note]
>
> If you already have quarto installed on your machine you can use it directly
> instead of `pixi`. The advantage of `pixi` is that you can "freeze" the quarto
> version for this project and avoid any issues if a future quarto version has
> different features or behaviour.

You must also get a copy of this repository on your machine. Use the following
link to download a zip file and decompress it somewhere:

<https://gitlab.in2p3.fr/lbbe/poleinfo/academic_website/-/archive/main/academic_website-main.zip?ref_type=heads>

> [!tip]
>
> It is recommended not to use `git` to clone this repository because you may
> want to create your own git repository inside it later.

To check that everything is working correctly, run the following command in the
project directory:

```shell
pixi run quarto preview
```

This should open a new tab in your browser displaying a preview of the default
example website.

## How this project works

### Website source code

The source code of your website is made of _content in
[markdown](https://en.wikipedia.org/wiki/Markdown) format_ and _configuration in
[YAML](https://en.wikipedia.org/wiki/YAML) format_.

The global configuration file is `_quarto.yml`, which is at the root of the
project.

Each website page is a text file with a `.qmd` extension. The start of the file,
between two sets of `---` characters, is called the _preamble_ and allows to
specify some configuration for the page itself. The rest of the file is the
content of the page in Markdown format.

Here is a sample website page, with a preamble which sets the page title, and
some content:

```md
---
title: Page title
---

# Section 1

Some text with **bold** and _italics_.

And a link to [a website](https://example.com).
```

The markdown syntax allows to add many different type of content such as links,
tables, images, figures, etc.

### Website generation

To create your website, you will edit its content in `qmd` files, define its
global configuration in `_quarto.yml`, and then run quarto commands to generate
a static website in the `_site` project subdirectory. This is the equivalent of
"compiling" a set of LaTeX files to a PDF, for example.

At the end, to publish your generated website only the content of the `_site`
directory is needed.

> [!note]
>
> A static website is composed of a set of files (HTML, CSS, images...) where
> nothing is generated dynamically and all visitors see the same fixed content.
> No software is involved server side as the website files are sent "as is" to
> each visitor. This means that a static website doesn't need any maintenance
> (there is nothing to keep up to date) and doesn't present any security risk.

There are two ways of generating your website: by _previewing_ or by _rendering_
it.

### Previewing your site

You can preview your website by running the following command in your project
directory:

```shell
pixi run quarto preview
```

This should open a new tab in your browser with a preview of your static
website. This preview is dynamic, which means that each time you change
something in your site content or configuration, the preview will be
automatically updated.

> [!tip]
>
> This preview mode is particularly useful when creating or modifying your site.

### Rendering your site

Rendering your website means generating all the files of yout website (HTML,
CSS..). This is done by running the following command in the project directory:

```shell
pixi run quarto render
```

This will create or update a `_site` folder in the project which will contain
your rendered static website. You can open the `index.html` file in this folder
with your browser to see it.

> [!note]
>
> The content of the `_site` folder is all that is needed to be put online so
> that your website can be accessible on the Web.

## Customizing your site

### Homepage

The homepage of your site is defined in the file `index.qmd`. Its YAML preamble
uses the [Quarto about feature](https://quarto.org/docs/authoring/about.html),
which turns the page into a personal presentation with a profile picture, social
links, and a short biography.

The YAML preamble of the page looks like the following:

```yaml
---
title: "Charles Darouine"
about:
  template: jolla
  image: assets/profile.jpg
  image-shape: round
  links:
    - icon: bluesky
      text: Bluesky
      href: https://bsky.app
    ...
---
```

- The `template` field allows to change the visual layout of the page. There are
  several templates available: `jolla` (the default), `trestles`, `solana`,
  `marquee` and `broadside`. You can see a
  [preview of each template](https://quarto.org/docs/websites/website-about.html#templates)
  in the quarto documentation.
- The `image` field is a path to the profile picture displayed on the page. By
  default it is the `profile.jpg` file in the `assets` folder, but you can
  change its value.
- `image-shape` changes the shape of the image for some templates. It can be
  `round`, `rectangle` or `rounded`.
- `links` is an optional list of icons linking to your social or contact
  profiles. You can add or remove icons, change their text, update their `href`
  field to point to your profiles. The `icon` field is the name of a
  [bootstrap icon](https://icons.getbootstrap.com) to be displayed along the
  link.

The markdown content after the YAML preamble will be used as the page text. It
will be put at different places depending on the template you choose.

Other available options to customize the homepage are described in the
[About pages section](https://quarto.org/docs/websites/website-about.html) of
Quarto documentation.

### Global site structure and configuration

The website structure and global configuration is defined in the `_quarto.yml`
file. This file is organized in different sections.

The `website` section defines the site structure. This template uses a top
navigation bar. The `left` block lists the pages to be displayed on the left of
this top bar, and the `tools` the icons displayed on the right.

```yaml
website:
  # website title
  title: "Charles Darouine"
  navbar:
    search: true
    # Pages to display at the left of the top bar
    left:
      - publications.qmd
      - teaching.qmd
    # Icons to display at the right of the top bar
    tools:
      - icon: bluesky
        text: Bluesky
        href: https://bsky.app
      ...
```

There are many other possible options, and it is even possible to switch to a
different navigation layout. This is described in the
[website navigation section](https://quarto.org/docs/websites/website-navigation.html)
of the Quarto documentation.

The `format` section and its `html` subsection allows to change the website
visual look.

```yaml
format:
  html:
    # Light and dark themes
    # Preview them at https://bootswatch.com/default/
    theme:
      light: cosmo
      dark: darkly
    css: styles.css
    # Add a table of contents to each page
    toc: true
```

The `theme` block allows to select `light` and `dark` themes. To have a preview
of all the available themes, you can go to the
[bootswatch gallery](https://bootswatch.com/default/) and select a theme in the
_Themes_ dropdown menu at the top.

More information can be found on the
[HTML Basics](https://quarto.org/docs/output-formats/html-basics.html) and
[HTML Theming](https://quarto.org/docs/output-formats/html-themes.html) sections
of Quarto documentation.

### Publications

The `publications.qmd` page proposes a layout that lists all publications from a
`biblio.bib` BibTeX file, as well as highlights some of these publications by
giving them their own page in the `publications` folder.

> [!note]
>
> These features are optional, you can also manage this page content manually if
> you prefer.

#### Complete list of publications

The following entries in the YAML preamble of `publications.qmd` define a BibTeX
file as a bibliography source.

```yaml
bibliography: biblio.bib
nocite: |
  @*
```

With this setting, the following code in your markdown content will be replaced
by a formatted list of all the publications:

```markdown
:::{#refs}

:::
```

It is possible to provide a
[Citation Style Language file](https://quarto.org/docs/authoring/citations.html#sec-citations-style)
to change the way references are formatted.

#### Major publications

The following block in the preamble of `publications.qmd` allows to create a
listing of some publications you want to highlight. The listing is made from all
the `.qmd` files in the `publications` folder.

```yaml
listing:
  id: publis
  type: grid
  contents:
    - "publications/*.qmd"
```

The listing is then added to the page content with the following block:

```markdown
::: {#publis}

:::
```

> [!note]
>
> It is possible to customize the listing presentation. See
> [Document listings](https://quarto.org/docs/websites/website-listings.html) in
> the Quarto documentation.

Each highlighted publication is a `qmd` file in the `publications` folder. These
files have quite a long preamble which allows to add bibliographical
informations: author, date, journal, etc.

It is recommended to add an `image` field to the preamble to add an image that
will be used in the listing.

The complete list of available options in the preamble are described in the
[Front matter](https://quarto.org/docs/authoring/front-matter.html) section of
Quarto documentation.

To add a new publication, you just have to create a new `<publication-name>.qmd`
file in the `publications` folder, add metadata in its preamble (at least an
image and a short description) and some markdown content.

### Adding a page to the site

If you want to add a new webpage to the site and make it appear in the top
navigation bar:

1. Create a new `.qmd` file at the project root, for example `research.qmd`,
   with a title in its YAML preamble:

   ```md
   ---
   title: "Research"
   ---

   My research interests...
   ```

2. Add it to the navigation bar in `_quarto.yml`:

   ```yaml
   website:
     navbar:
       left:
         - publications.qmd
         - teaching.qmd
         - research.qmd
   ```

The new page should now appear in the site header.

> [!tip]
>
> You can link to a page from another page by creating a relative link to its
> qmd file, for example `[research](research.qmd)`.

### Page content

The content of a page is written in Markdown, which allows for basic markup:

- Level 1 heading starts with `# `, level 2 with `## `, etc.
- Text can be put in `**bold**` or `*italic*`
- It is possible to create list items by beginning a line with `- `, numbered
  items by beginning with `1. `, etc.
- Links are created with the syntax `[link title](https://example.com)`
- Images can be inserted with the syntax `![caption](/path/to/image.jpg)`

Markdown formatting is described in the
[Markdown basics](https://quarto.org/docs/authoring/markdown-basics.html) Quarto
documentation.

Quarto provides extensions to Markdown that allow for more complex formatting or
layout:

- [Figures](https://quarto.org/docs/authoring/figures.html) with caption and
  resized image, optionnaly with
  [lightbox effect](https://quarto.org/docs/output-formats/html-lightbox-figures.html)
  (zoom image on click)
- [Tables](https://quarto.org/docs/authoring/tables.html)
- [Videos](https://quarto.org/docs/authoring/videos.html)
- [Complex article layouts](https://quarto.org/docs/authoring/article-layout.html)

All the options are described in the
[authoring section](https://quarto.org/docs/authoring/markdown-basics.html) of
the Quarto documentation.

## Publishing your website online

There are many alternatives to publish your static website online. Here we only
briefly present three of them.

### Github pages

> [!note] Pros and cons
>
> - **Pros:** free, performant, integrated with git, relatively easy to setup,
>   continuous integration possible, own domain name possible
> - **Cons:** hosted by a private company, dependance on the service and its
>   evolutions

Github pages is a service which allows to deploy a static website hosted on a
Github repository.

To use Github pages, you have to create a github repository and store your
project inside it.

> [!note]
>
> By default, if your github username is `cdarouine` and your Github project is
> names `about`, the URL of your website will be
> <https://cdarouine.github.io/about>. But if you name your repository
> `cdarouine.github.io`, it will be accessible directly at
> <https://cdarouine.github.io>.

Once this is set up, there are two possible ways to deploy your site on Github
pages: manually, or via continuous integration.

#### Manual compilation and deployment

This method of deployment means that you add the `_site` folder to your Github
repository and tell Github to use it as the source of your pages.

When a new version of your website is ready on your machine and you want to
deploy it, you have to run `pixi run quarto render`, commit the `_site`
directory, and push it to Github. The new version will then be available after a
few minutes.

To set this up:

1. On Github, go to your website project and click on _Settings_. In the
   sidebar, click on _Pages_. In _Build and deployment_, select "deploy from a
   branch" in ths _Source_ field. In the _branch_ field, select your `main`
   branch, and then select the `_site` folder and click save.
2. On your machine, open the `.gitignore` file at the root of the project and
   remove the line `_site`.

After this, if you commit and push changes to your local `_site` folder, they
should be published at the URL of your repository Github pages.

#### Continuous integration deployment

This method of deployment means that each time you push a commit to the _source
code_ of your site, Github will run an action on his servers that will render
and deploy your website to Github pages. This means that the `_site` folder is
not commited to the github repository, only the source code is, and you are sure
that the published version corresponds exactly to the source code of your `main`
branch.

To do this, create a file in the project called `.github/workflows/publish.yml`
with the following content (replace EMAIL and NAME with your real email and
name):

```yaml
on:
  workflow_dispatch:
  push:
    branches: [main]

name: Website

jobs:
  Build-deploy:
    runs-on: ubuntu-latest
    permissions:
      contents: write
    steps:
      - name: Check out repository
        uses: actions/checkout@v7

      - name: Setup pixi
        uses: prefix-dev/setup-pixi@v0.11.3
        with:
          cache: true

      - name: Render and Publish
        shell: bash
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
        run: |
          git config --global user.email "EMAIL"
          git config --global user.name "NAME"
          pixi run quarto publish gh-pages doc
```
